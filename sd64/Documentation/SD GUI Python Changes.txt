AI summary of what changed:
The modification makes the GUI responsive through **cooperative scheduling**:

1. BASIC periodically calls `SD_PyGuiStep`.
2. `SD_PyGuiStep` runs a bounded number of Tkinter events using nonblocking `dooneevent()`.
3. Tkinter callbacks execute briefly and call `sd.post_event()`.
4. `sd.post_event()` copies the event into a mutex-protected C queue and writes to the wakeup pipe.
5. BASIC then calls `SD_PyPoll`, which removes one queued event and returns it to BASIC.
6. BASIC handles the event without Python re-entering the VM asynchronously.

The `pollfd` change allows SD to notice Python activity while waiting on input. It records Python readiness and drains the notification pipe, but does not execute BASIC from inside `sdpoll()`, avoiding VM re-entry and stack corruption.

The GUI remains responsive because each GUI step is bounded by an event count/time limit. The important limitation is that BASIC must continue reaching `SD_PyGuiStep`; if it is blocked indefinitely in a synchronous operation, the GUI cannot be serviced by this cooperative model alone.
